# Основы и фундаментальные принципы
Игра на Override состоит из сцен. Сцены - обычные lua файлы с игровой логикой, при старте программы движок запускает сцену `main.lua`. Внутри сцены описывается игровая логика(в основном это создание и последующая работа с GameObject).

При загрузке новой сцены движок автоматически сбрасывает своё состояние, вам не нужно ничего вручную удалять. Для ознакомления работы со сценами посмотрите документацию к модулю `override`.

Объект - основная еденица вашей игры, он может быть как и слоем в который можно вставлять другие объекты для группировки(аналог display.newGroup() из Solar2d(Corona SDK) либо ноды из Godot, ко второму объект override относится наиболее близко)

Вы всё время будете сталкиваться с работой с объектами, и очень важно понимать что объекты override это не простые луа таблицы, а объекты `userdata`. Это налаживает ряд ограничений: к примеру вы не сможете записать в объект свойство что не было в нём объявлено движком
```lua
local a = display:circle(0,0,50)
a.input = 0 --код упадёт с ошибкой, так делать нельзя
--== Для хранения кастомных полей у всех объектов есть встроенная таблица data, туда можно писать что угодно ==--
a.data.input = 0 --так делать правильно, data является объектом родным для lua
```
Так же для объектов специфично поведение где всё разделено на поля(.) и методы(:).
```lua
local a = display:circle(0,0,50)
a:on() --правильно
a.on() --код упадёт с ошибкой, так как фреймворк ожидал сам объект перым аргументом, знак : передаёт его автоматически

a.radius = 30 --правильно
a:radius = 30 --неправильно с точки зрения самого lua
```
Главной причиной для реализации такого поведения является оптимизация. Override легко выдерживает бенчмарки где схожий Solar2d не способен справиться упираясь в мост.
